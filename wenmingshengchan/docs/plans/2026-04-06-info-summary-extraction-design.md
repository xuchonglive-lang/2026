# 信息列表“摘取摘要”功能设计方案 (Option C)

## 核心设计思路
采用**非侵入式的“表单引导 + 服务端降级兜底”策略**。既满足管理员人工干预摘要展现的高级创作需求，又保障普通录入时免除繁琐操作的信息快速流转。

## 涉及层面

### 1. 视图表现层 (Admin UI - `info-list.vue`)
- 在发布的弹框配置（`form1.props.columns`）中，紧挨着“文章标题”的下方补充挂载 `summary` (内容摘要) 字段。
- 字段呈现控件采用 `textarea` 多行输入类型，设定占位符提示文案为：“请撰写引人入胜的内容提要（选填。若留空，系统发布时将自动截取正文首段做摘要）”。
- 为其配置 `maxlength="200"` 与 `show-word-limit: true`，严控在列表展示时的视觉溢出。

### 2. 服务端引擎层 (Cloud functions)
- 保持此前我们在 `admin/info/detail/sys/add.js` 和 `update.js` 内部建立起的自摘要切片拦截器。
- 接收到客户端载荷后，评议 `summary` 字段。若被显式填写，直接入库；如果为空（或未投送），利用正则表达式清洗富文本 `content` 所包裹的所有 HTML 标签痕迹及符号，再严谨地拉取首 60 字符生成系统摘要完成入库。 

## 测试用例考量
- 仅填写标题+正文并选择分类保存 -> 预期自动在首屏产生正确截取的纯字版摘要
- 填好长正文后，手动在提要档写上 5 个字保存 -> 列表预期只展示这明确指定的 5 个字。
