# 重控点位监督管理变更 - 指定照片标题设计方案

**日期**：2026-04-23
**状态**：设计已确认

## 1. 业务背景与需求
在原有的重控点位监督管理模块变更提案中，计划将照片统一为最多三张的 `images` 数组。
本次新增核心需求：**B端配置时可为每一张需要上传的照片指定具体的标题**（如：“现场全貌图”、“整改前细节图”），C端工友在上传时必须根据这些具体标题进行对应槽位的照片上传。此举旨在进一步规范反馈质量，避免现场照片杂乱无章。

## 2. 核心架构决策
采用 **B端配置驱动 + C端对象数组快照** 模式。
*   配置表存储所需的标题数组。
*   反馈记录表存储包含标题和URL的对象数组（快照），确保历史数据具备绝对的防腐性，即使未来B端修改了标题，历史审核记录仍能真实还原上传时的标题要求。

## 3. 详细设计说明

### 3.1 数据库结构
*   **点位配置表 (`key-point-config`)**
    *   **废弃**：原定的 `required_photo_count`。
    *   **新增**：`photo_requirements` (Array<String>)，用于存放必传照片的标题列表。数组长度上限为3。
    *   *示例*：`["现场全貌图", "违规细节图"]`

*   **反馈记录表 (`key-point-feedback`)**
    *   **结构变更**：`images` 字段由 `Array<String>` 升级为 `Array<Object>`。
    *   *数据结构*：`[{ title: String, url: String }]`
    *   *示例*：`[{ title: "现场全貌图", url: "cloud://..." }, { title: "违规细节图", url: "cloud://..." }]`

### 3.2 B端后台 (`mp-admin`)
*   **点位配置 (`pages/feedback/point-config.vue`)**
    *   移除原有的数量单选框。
    *   实现动态输入列表，管理员可点击“新增照片要求”，录入具体标题（最多3条），前端将其转为 `photo_requirements` 数组提交。
*   **审核详情展示 (`pages/feedback/feedback-list.vue` 及相关弹窗)**
    *   将单纯遍历图片链接的逻辑，更改为遍历 `images` 对象数组。
    *   在 UI 上，每张图片的顶部或底部醒目展示该图片的 `title`。
    *   兼容性处理：若遇到旧版纯字符串数组的图片数据，给予默认的“现场照片”占位标题。

### 3.3 C端前台 (`mp-client`)
*   **上传槽位渲染 (`pages/feedback/submit/index.vue`)**
    *   拉取到点位的 `photo_requirements` 后，使用 `v-for` 渲染出对应数量的独立上传组件槽位。
    *   每个槽位上方带有红色星号和指定的标题（例如：`*现场全貌图`）。
    *   每个独立组件的 `limit` 限制为1。
*   **提交校验逻辑**
    *   用户点击提交时，遍历检查各个槽位是否都已上传成功并获取到云URL。
    *   若有缺失，触发阻断提示 `vk.toast('请上传[xxx]的照片')`。
*   **数据组装**
    *   上传校验通过后，按槽位映射组装成 `[{title: '...', url: '...'}]` 结构，作为 `images` 参数传递给 `submitFeedback` 云函数。
