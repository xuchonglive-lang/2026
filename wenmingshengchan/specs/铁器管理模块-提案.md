# 铁器管理模块新增功能提案

**创建时间**：2026-05-13
**状态**：已确认（2026-05-13）
**背景说明**：
采选生产流程中，铁器作为影响设备安全与工艺质量的关键风险因子，目前缺乏系统化的全流程追溯管理手段。为满足"源头追溯、过程管理痕迹留存、定期巡检合规"的监管要求，需在现有系统中新增**铁器管理模块**，涵盖铁器登记、奖励性发现反馈、周期性巡检三个核心子功能，并辅以基础字典配置管理，形成从"源头登记 → 现场上报 → 定期巡查"的闭环管理体系。

---

## 一、功能总览

| 功能编号 | 功能名称 | 功能类型 | 参与角色 | 管理目标 |
|---------|---------|---------|---------|---------|
| TQ-01 | 铁器登记管理 | 台账录入 + 检索 | **部门管理员及以上**（录入）、所有用户（查看） | 对进入采选流程的铁器进行源头追溯 |
| TQ-02 | 奖励性发现反馈 | 激励上报 + 统计汇总 | **部门管理员及以上**（录入）、超级管理员（管理） | 留存过程管理痕迹，统计各部门铁器收集情况 |
| TQ-03 | 周期性巡检管理 | 派单巡查 + 反馈分析 | 被指定责任人（反馈）、所有用户（查看）、超级管理员（配置） | 确保关键点位定期受检，形成巡检周期分析 |
| TQ-04 | 基础字典管理 | 增删改查配置 | 超级管理员 | 维护使用点位/发现部位字典、铁器类型字典，供业务端下拉选择 |

## 二、数据库模型设计

### 2.1 铁器类型字典表（`iron-type-dict`）[新增]

由超级管理员在B端维护，供前端录入时下拉选择。

| 字段名称 | 类型 | 必填 | 示例值 | 说明 |
|---------|------|------|-------|------|
| `name` | String | ✅ | `"工具类"` | 铁器类型名称 |
| `sort` | Number | ✅ | `10` | 排序值，数值越小越靠前 |
| `status` | Number | ✅ | `1` | 状态（0-停用 / 1-启用） |
| `created_at` | Timestamp | ✅ | `1747123200000` | 创建时间 |

### 2.2 铁器部位点位字典表（`iron-location-dict`）[新增]

由超级管理员在B端维护，统一管理铁器的"使用点位"与"发现部位"，供前端下拉选择。

| 字段名称 | 类型 | 必填 | 示例值 | 说明 |
|---------|------|------|-------|------|
| `name` | String | ✅ | `"二楼破碎区A段"` | 点位/部位名称 |
| `sort` | Number | ✅ | `10` | 排序值 |
| `status` | Number | ✅ | `1` | 状态（0-停用 / 1-启用） |
| `created_at` | Timestamp | ✅ | `1747123200000` | 创建时间 |

存储每一条经人工录入的铁器基础信息，作为铁器追溯的源头台账。

| 字段名称 | 类型 | 必填 | 示例值 | 说明 |

| `location_id` | String | ✅ | `"loc001"` | 使用点位ID（关联部位点位字典） |
| `location_name` | String | ✅ | `"二楼破碎区A段"` | 使用点位名称（快照） |
| `dept_id` | String | ✅ | `"001"` | 使用部门ID（关联部门表） |
| `dept_name` | String | ✅ | `"破碎车间"` | 使用部门名称（冗余快照） |

| `iron_type_name` | String | ✅ | `"工具类"` | 铁器类型名称（快照） |

| `images` | Array\<String\> | ✅ | `["url1","url2"]` | 铁器照片（云端URL列表） |

## 三、功能详细说明

### 功能 TQ-04：基础字典管理（先行实现）

**角色：超级管理员（B端 `mp-admin`）**

- 新建页面 `pages/iron/dict/location.vue`：对**部位点位字典**（`iron-location-dict`）进行增删改查。维护铁器使用点位与发现部位的统一库，支持排序与启停用。
- 新建页面 `pages/iron/dict/type.vue`：对**铁器类型字典**（`iron-type-dict`）进行增删改查。维护类型列表（如：工具类、紧固件类、异物类等），支持排序与启停用。
- **业务约束**：被业务数据引用的字典项建议仅修改名称或停用，不建议物理删除以保数据完整性。C端下拉列表仅加载 `status === 1`（启用）的字典项。

### 功能 TQ-01：铁器登记管理

#### 3.2.1 C 端（`mp-client`）

**角色：部门管理员 / 超级管理员**

- 新建页面 `pages/iron/register/submit.vue`，提供铁器信息录入表单。
- 表单字段：
  - 铁器名称（文本）
  - **使用点位**（下拉选择，数据动态读取 `iron-location-dict` 的启用项）
  - 使用部门（下拉选择，数据来源部门表）
  - **铁器类型**（下拉选择，数据动态读取 `iron-type-dict` 的启用项）
  - 用途（文本）
  - 照片上传（普通照片多张）
  - 对流程的破坏程度（单选：低/中/高）
- 录入人、录入人单位由系统自动从登录用户信息中读取，不可手动填写。
- 提交成功后返回列表页。

**角色：所有用户**

- 新建页面 `pages/iron/register/list.vue`，展示铁器登记台账列表。
- 支持检索条件：铁器名称（模糊）、使用部门（下拉）、**铁器类型**（下拉读取字典）。
- 列表展示：铁器名称、使用部门、铁器类型、使用点位、录入人、录入时间。
- 点击列表项可查看详情（含照片）。
- **权限控制**：编辑/删除按钮仅对部门管理员及以上角色展示；录入时间超24小时后按钮置灰；超级管理员始终可操作。

#### 3.2.2 B 端（`mp-admin`）

**角色：超级管理员**

- 新建页面 `pages/iron/register/list.vue`，展示全量铁器登记台账。
- 提供录入入口（弹窗或跳转表单页），字段与C端一致，点位和类型同样使用下拉字典。
- 支持按铁器名称、部门、类型、录入时间范围检索。
- 支持修改、删除任意记录（不受24小时限制）。
- 支持导出表格功能（Excel/CSV），用于统计分析。

### 功能 TQ-02：奖励性发现反馈

#### 3.3.1 C 端（`mp-client`）

**角色：部门管理员及以上**

- 新建页面 `pages/iron/reward/submit.vue`，提供铁器发现上报表单。
- 表单字段：
  - 铁器名称（文本）
  - **发现部位**（下拉选择，数据动态读取 `iron-location-dict` 的启用项）
  - **铁器类型**（下拉选择，数据动态读取 `iron-type-dict` 的启用项）
  - 现场照片（普通照片上传，支持多张）
  - 责任单位（下拉选择，数据来源部门表）
- 录入人、录入人单位由系统自动从登录用户信息中读取，不可手动填写。
- 录入时间超24小时后不得修改或删除，仅超级管理员可操作。

#### 3.3.2 B 端（`mp-admin`）

**角色：超级管理员**

- 新建页面 `pages/iron/reward/list.vue`，展示全量奖励性反馈记录。
- 支持按录入人单位汇总统计，展示各单位的上报条数。
- 支持按时间范围检索。
- 支持导出表格（Excel/CSV），用于统计分析与绩效评估。
- 支持查看详情（含现场照片）。

### 功能 TQ-03：周期性巡检管理

#### 3.4.1 B 端配置（`mp-admin`）

**角色：超级管理员**

- 新建点位配置页 `pages/iron/inspect/point-config.vue`：
  - 支持新增/编辑/删除巡检点位配置。
  - 配置字段：点位名称、巡检标准（文本域）、巡检周期（天数，数字选择）、责任反馈人（多选，从用户列表选取）、启用状态。
  - 发布（启用）后，系统自动生成第一条待反馈记录；此后每次责任人提交反馈后，自动滚动生成下一周期记录。
- 新建巡检记录管理页 `pages/iron/inspect/record-list.vue`：
  - 按点位、周期、反馈状态筛选查看全量巡检记录。
  - 可对每条已反馈记录进行点评（填写 `admin_comment`）。
  - 支持查看各点位的**周期反馈分析**：反馈率、逾期率的趋势图表。

#### 3.4.2 C 端（`mp-client`）

**角色：所有用户**

- 新建巡检记录查看页 `pages/iron/inspect/record-list.vue`：
  - 展示所有点位的当前周期巡检状态（待反馈/已反馈/逾期）。
  - 支持按点位名称、反馈状态筛选。

**角色：被指定为责任反馈人的用户**

- 在个人待办或独立入口可看到本人负责的待反馈巡检任务。
- 点击任务进入反馈提交页 `pages/iron/inspect/submit.vue`：
  - 自动带入点位名称、巡检标准、周期信息（只读展示）。
  - 填写字段：巡检结果描述（文本域）、现场照片（选填）。
  - 提交后记录状态变为"已反馈"，系统自动创建下一周期待反馈记录，管理员可在B端查阅并点评。
- 可查看管理员对本人历史反馈的点评内容。

## 七、关键业务规则

### 7.1 24 小时编辑限制（TQ-01 / TQ-02 通用）

云函数在处理修改/删除请求时，需进行如下校验：

```
if (当前时间 - created_at > 24小时) {
  if (操作者角色 !== "superAdmin") {
    return 错误("已超过24小时，无权修改或删除")
  }
}
```

与现有"个人中心记录管理"模块中的同类逻辑保持一致，可提炼为公共校验工具函数复用。

### 7.2 周期性巡检任务自动滚动生成机制（TQ-03）

采用**提交触发滚动**模式，具体流程如下：

1. 超级管理员**发布（启用）**某巡检点位配置后，`addInspectPoint.js` 立即在 `iron-inspect-record` 中生成第一条待反馈记录（`status: 0`），`period_start` 为当前时间，`period_end` = `period_start + period_days × 86400000`。
2. 责任人提交反馈后（`status → 1`），`submitInspectRecord.js` 在同一事务中自动创建下一周期记录（`status: 0`，`period_start` = 上一条 `period_end`），实现**无缝滚动派单**。
3. 若到达 `period_end` 时记录仍为 `status: 0`，系统在下次查询时（惰性清算）将其标记为 `status: 2`（逾期未反馈），并触发生成新一周期记录，不中断巡检流程。

### 7.3 照片上传与字典动态读取

1. **照片上传**：铁器登记与奖励性反馈均使用**标准照片上传组件**，支持拍照或从相册选取，无水印要求。复用现有 `u-upload` 封装组件。
2. **字典读取**：C端/B端表单中的"铁器类型"、"使用点位/发现部位"均由接口动态从对应的字典表中拉取（仅拉取状态为启用的记录），不再前端硬编码。

## 八、风险与防护

1. **字典变更的数据一致性**：若字典项名称在B端被修改，历史业务记录中由于保存了名称快照（如 `iron_type_name`），历史记录展示不受影响；若需要同步更新历史数据，建议在字典更新的云函数中做级联更新，或禁止修改字典名称，仅支持新增与停用。
2. **与现有重控点位模块的边界**：周期性巡检（TQ-03）与现有重控点位监督管理模块在逻辑上高度相似，开发时注意参照已有架构，但数据库表与页面路由须保持独立，避免业务数据混淆。
3. **巡检记录滚动生成的幂等性**：周期记录的自动生成必须具备幂等性保护（如按 `point_id + period_start` 联合唯一索引），防止因网络重试导致重复创建同一周期记录。
4. **导出功能**：B端的表格导出（TQ-01/TQ-02）建议支持按当前检索条件导出筛选结果，文件格式统一为 Excel `.xlsx`。
