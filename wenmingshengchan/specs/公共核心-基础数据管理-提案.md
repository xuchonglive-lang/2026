# 功能规格说明：基础数据管理

**功能分支**：`[feat-base-data-management]`  
**创建时间**：2026-04-04  
**状态**：草稿  
**模块类别**：公共核心  

## 一、模块概述
本模块负责维护和管理整个系统的底层基石数据，包括系统的身份认证体系（微信授权、角色与权限分配）、组织架构树（公司-部门-小组三级架构），以及现场生产相关的空间数据基座（作业区域、作业点位）。所有其余业务模块均需依赖本模块的数据进行关联绑定与权限计算。

## 二、用户场景与用户故事

### 用户故事 1 - 微信授权与用户信息完善 (优先级：P1)
**场景描述**：作为一名新入职或首次使用小程序的矿业员工，我需要通过微信一键授权登录，并在第一次登录时完善我的姓名、手机号以及所属部门和小组，以便能正常使用系统汇报工作。
**优先级的理由**：这是前台小程序所有业务操作的基础准入条件，没有实名注册与部门归属，将无法定位任何一条汇报业务数据的责任人。
**验收场景**：
1. **假设** 我是第一次打开小程序的新账号，**当** 我试图访问首页时，**那么** 系统自动唤出微信授权弹窗获取头像与昵称。
2. **假设** 我微信授权成功但未完善信息，**当** 系统进行状态校验后，**那么** 会强制跳转至“信息注册页”，要求我填写姓名、手机和归属（二级级联选择：部门-小组）。
3. **假设** 我提交了完善信息，**当** 信息进入待审状态，**那么** 我的任何操作都会被重定向至“待审核提示页”。

### 用户故事 2 - 会员账号管理审核机制 (优先级：P1)
**场景描述**：作为部门管理员或超级管理员，我需要定期在后台审核新员工的注册申请，或者变更调整现有员工的状态以防系统资源被非在场人员滥用。
**验收场景**：
1. **假设** 部门管理员登录后台，**当** 进入会员列表时，**那么** 他只能看到其所管辖的该部门下方（及其包含的小组）的用户，并可以点击“通过”或“拒绝”待审用户。
2. **假设** 员工已离职，**当** 超级管理员在用户列表中点击“禁用账号”，**那么** 该员工再也无法通过微信从小程序端登录访问任何内部数据界面。

### 用户故事 3 - 三级组织架构(部门小组)维护 (优先级：P2)
**场景描述**：作为超级管理员，随着公司架构优化，我需要通过后台增加新的部门和生产小组，使其在前台的注册级联选择器和后台的点位委派中可用。
**验收场景**：
1. **假设** 人事发布了新成立部门通知，**当** 超管在“部门管理”页面新增该部门及下属小组后，**那么** 这会立即作为备选项反映在新用户注册或编辑页的级联菜单中。
2. **假设** 某历史部门被注销，且名下仍关联了历史用户，**当** 管理员尝试彻底删除该部门时，**那么** 系统应给出阻断拦截提示，仅允许操作为“禁用”而非“物理删除”。

### 用户故事 4 - 作业区域与点位维护 (优先级：P2)
**场景描述**：作为超级管理员，我需要录入矿区的各个作业区域（如采矿场、选矿厂等），并在区域下划定明细点位，这样才能在后续把防患安全和文明生产责任委派给具体部门或人员。
**验收场景**：
1. **假设** 现场新增一处洗选流水线，**当** 管理员在系统中新增“作业点位”并选择对应“作业区域”时，**那么** 系统能自动根据该区域联动默认加载相关的负责部门信息。
2. **假设** 某作业点位已被设置为“重控点位”，**当** 尝试进行删除操作时，**那么** 系统应提示拦截只允许修改点位状态为下线，不可硬性删除。

## 三、页面与路由设计

### C端页面设计（mp-client）
1. **登录授权页**：`/pages/user/login` (遵循最新微信隐私新规，抽离出通用的 `<AuthDialog>` 组件，利用 `open-type="chooseAvatar"` 和 `type="nickname"` 触发原生隐私协议并获取用户头像与昵称)
2. **信息注册完善页**：`/pages/user/register` (收集姓名、手机、部门、小组)
3. **审核状态提示页**：`/pages/user/audit-status` (提示审核中或被拒绝)
4. **我的个人中心**：`/pages/user/mine` (展示身份卡片及四类历史记录导航)

### B端页面设计（mp-admin）
1. **会员审核列表页**：`/pages/baseinfo/user/list`
2. **部门组织架构页**：`/pages/baseinfo/dept/list` (采用**左树右表**交互，左侧点击树形节点自动刷新右侧列表；表单内联上级部门支持 `cascader` 级联择取，符合 `vk-data-form` 组件规范)
3. **作业区域管理页**：`/pages/baseinfo/area/list` (包含管辖部门的 `cascader` 必查选控件)
4. **作业点位管理页**：`/pages/baseinfo/point/list` (包含区域 `remote-select` 以及 部门分管的 `cascader`)

## 四、接口与云函数设计

### C端云函数 (`/router/service/client/user/`)
- `loginByWeixin`: 实现微信小程序静默登录获取openid并绑定或构建uni-id账户。
- `updateUserInfo`: 提交验证真实姓名、手机、部门信息。
- `getMineProfile`: 拉取“我的”页面的个人展示资料。

### B端云函数 (`/router/service/admin/baseinfo/`)
- `/user/getList`: 获取含部门树查询能力、审核状态过滤的会员列表。
- `/user/updateStatus`: 将用户资料审阅为通过/拒绝/禁用。
- `/dept/getTree`: 输出严格意义上的（公司-部门-小组）层级树以供前后台联动选择。
- `/dept/add` | `update` | `delete`: 对部门架构CRUD。
- `/area/getList` / `/point/getList`: 表格获取区域与点位信息配置。
- `/point/add` | `update` | `delete`: 通过联动逻辑创建防患监测点。

## 五、数据与字段设计

### 1. `uni-id-users` 表扩展字段
- `_id`, `wx_openid`, `nickname`, `avatar` (内置及微信基础)
- `real_name` (String): 真实姓名
- `mobile` (String): 手机号码
- `department_id` (String): 关联三级架构中的直接所在一级部门ID
- `group_id` (String): 关联三级架构中的直接所在二级班组/小组ID
- `role` (Array): ['user', 'dept_admin', 'super_admin']
- `audit_status` (Number): 0(未提交完善), 1(待审核), 2(拒绝), 3(通过审核)
- `status` (Number): 0(正常), 1(禁用)

### 2. 基建部门树 `base-dept`
- `_id`
- `parent_id` (String): 父级ID，顶层空则默认为马城矿业公司
- `name` (String): 部门/小组名称
- `manager` (String): 负责人姓名
- `sort` (Number): 排序展示权重
- `status` (Number): 是否启用(1启/0禁)

### 3. 作业区域 `base-area`
- `_id` 
- `name` (String): 区划名
- `manager_dept_id` (String): 归属的权责部门ID，对应到基建部门树主职部门
- `remark` (String)
- `status` (Number)

### 4. 作业点位 `base-point`
- `_id`
- `area_id` (String): 所挂载作业区域ID
- `name` (String): 点位详情名称
- `manager_dept_id` (String): 继承自作业区域或重置下发的责任部门ID
- `remark` (String)
- `status` (Number)

## 六、开发约束与规范
- 根据宪章，用户资料完善需在前端利用 `vk.userCenter.loginByWeixin` 获取基础标识，**严禁使用已被微信回收的旧版 `getUserProfile`**。
- **头像昵称授权规范**：必须参照 `mp-login` 案例，使用原生安全机制：即通过含有 `uni.requirePrivacyAuthorize` 加持的 `<input type="nickname">` 获取名称，通过 `<button open-type="chooseAvatar">` 截获头像。
- “我的页面”中的各业务查询，由于跨模块联动，由前台页面基于角色及状态计算并动态显示列表入口。
- 用户状态的每次校验需强制作为系统层级 `loginFilter` 中间件实施，保证无论在任何路由入口只要没通过审核均受制约。

## 七、UI/UX 工业级视图及 1:1 页面复刻标准
为了保证符合文明生产系统的重工业后台质感与现代化体验，前端样式必须1:1严格复刻原型 (`docs/UI`)，服从以下最高视觉法则：
1. **工业玻璃拟物风 (Industrial Glassmorphism)**
   - 全局底层骨架：使用 `industrial-grid` (8px或24px点阵/网格的径向或线性渐变) 与 `bg-gradient-to-br from-surface to-primary-fixed`。
   - 浮动层与卡片 (`glass-card`)：使用低透明度白底 `bg-white/25 backdrop-blur-[20px] border border-white/20`，匹配具有环境反射光的阴影 `ambient-glow: 0 8px 32px 0 rgba(0,80,203,0.08)`。
2. **Typography 与 排版布局**
   - 标题级全量强制采用 `Manrope` 字体 (`font-headline`)。
   - 详情文本与数据区采用 `Inter` 字体 (`font-body`)。
   - 数据面板与指标推荐使用 `Fira Code` 或紧凑型无衬线黑体强化科技感。
3. **动作与微交互 (Micro-interactions)**
   - 所有按钮和可点击面板均采用重工业级阻尼反馈：`cubic-bezier(0.2, 0.8, 0.2, 1)` (duration 300ms)。点击时叠加缩放反馈机制如 `active:scale-95`。
4. **组件落标要求**
   - **登录/注册/审核/我的** 等页面，所有UI元素的坐标、颜色、阴影半径与间距必须精确抽取自所供 HTML 锚点设计素材，做到 1:1 结构吻合，不可采用廉价组件拼凑。
   - 图标一律使用 `Material Symbols Outlined`，严禁夹带系统Emoji符号。

## 七、核心业务防患与逻辑约束（经头脑风暴确认）

### 1. 严格单属原则 (Strict Single Affiliation)
- 每个员工仅能在 `uni-id-users` 中绑定一对 `department_id` 和 `group_id`（String类型，非数组）。系统拒绝一人跨多部门或多班组并发，通过最底层的强关联极大简化后续数据鉴权的复杂度。且写入时严格校验组必须归属于该部门，防止逻辑血缘错乱。

### 2. 死锁拦截守卫 (Deadlock Interception for Audit)
- 当用户进入 `audit_status = 2` (认证被拒绝) 时，前端直接渲染硬性死结页面提示联系管理员。切断原路返回修改入口，避免恶意探测和脏数据反复涌入，只有线下沟通管理员解除方可重新操作。

### 3. 数据大盘树状下钻隔离 (Tree-based Penetration Visibility)
- 在 B 端后台执行核心列表及单据查询时，部门级管理员（`dept_admin`）获取的数据可见范围遵循自上而下的树状遍历。
- 逻辑提取：传入本人 `department_id` -> 递归 `base-dept` 表拿取自己加上所有级联子部门/班组的 ID 集 -> 拼接为 `JQL dbCmd.in(...)` 条件进行数据捞取。

### 4. 强制生命周期依赖校验 (Lifecycle Dependency Defense)
- **禁止连坐封禁，保全业务**：任何时候管理员尝试将具有关联历史用户（`status === 0`活跃状态）的部门、或具有下属点位的作业区域标记为“下线”（状态禁用）时，云服务端必须提前通过 `count()` 指令计算残余活跃数。发现孤儿数据可能产生，即强行扔出异常阻击写库，提示管理员必须先行手动转移人口及资产属性。

### 5. 区域-点位智能继承联动 (Area-Point Sync)
- 后台创建作业点位并选择作业区域归属时，需触发钩子：拉取出该区域绑定的默认 `manager_dept_id`（责任管事部门），并直接覆盖回填到正在编辑的点位表单中作为默认配置。
- 允许后续表单独立自由修改权责发生分离（如特种设备的越级指派）。
