# 功能规格说明：专业信息传达管理

**功能分支**：`[feat-info-publish]`  
**创建时间**：2026-04-04  
**状态**：草稿  
**模块类别**：业务核心  

## 一、模块概述
本模块承担了平台内部的信息中枢作用，由高权限管理员或宣传科室通过后台发布安全守则、通报批评、文明生产标准文档及新闻资讯等富文本类信息。前台小程序端为员工展示一个可水平切换分类版图结构的信息广场并供以强制贯通展示及追踪记录。

## 二、用户场景与用户故事

### 用户故事 1 - 多媒体文章排版发布 (优先级：P1)
**场景描述**：宣传主管需针对新下发的《春季矿区防火特安通知》发出一篇包含大量图文内容并排版复杂的通告至小程序的信息端以供全员学习。
**验收场景**：
1. **假设** 主管位于后台添加信息页并启动了基于 `custom-editor-tinymce` 的富文本编辑器进行排版，**当** 其将复杂样式图片及引文录入进去归属在“安防章程”类目点击发布后，**那么** 该文章状态转变为在架并能被小程序即用即展。
2. **假设** 已发布文章被发现文字错误，**当** 执行一键“下架”操作后，**那么** 此信息同时在客户端瞬间隐藏。

### 用户故事 2 - 员工信息广场检索与翻阅历程捕捉 (优先级：P1)
**场景描述**：作为被动接受培训或教育的用户，我能在日常休息时浏览各板块新下发的各类通报，系统需支持紧急且重要的通告实现显著的置顶推荐展示。由于查阅具有考核属性，主管能够查阅我确信已读的后台痕迹，同时作为个人方便复盘回味，我能在“我的”中心随时找回已被历史掩埋但个人早前查阅过的文章记录。
**验收场景**：
1. **假设** 我登录上首页通过入口点进去新闻资讯卡片，**当** 拨动横向标签页到“安全通知”模块，**那么** 会出现包含有特异高亮标签且稳居列表首位的全公司置顶通知，其余跟随的则是随时间递减呈现的普通标题。
2. **假设** 某些文章我曾点开过并在云端完成了防伪签收，**当** 我进入个人中心的“我的浏览痕迹”独立页面，**那么** 便能不受分类约束地按倒序轻松重温名下涉及过的查阅档案。

## 三、页面与路由设计

### C端页面设计（mp-client）
1. **信息广场列表枢纽**：`/pages/info/index` (为扩大核心阅读视野已移除全局顶部导航栏；在主标题下方引入局部 uView 搜索枢纽及横向滚动分类条；底部承载全局五栏式 `custom-tab-bar`；主体全盘引入业界标杆 `z-paging` 组件库实现丝滑下拉刷新与拉底加载，包含自动拦截分类首位置顶文章转化呈现为超级大图画板视觉的特有置换体系排版)
2. **富文本文章呈递深读页**：`/pages/info/detail` (全屏展现，运用 uView 的 `u-parse` 组件重构解析 HTML 富文本的视觉输出界面)
3. **我的浏览足迹归档册**：`/pages/user/read-history` (由“我的”面板挂载入口独立全屏跳页，同样以 `z-paging` 为分页基载体承托，展示连表关联的用户单项倒序历程清单)

### B端页面设计（mp-admin）
1. **文章类目元数据管理**：`/pages/info/category-list` (配置可横向拨拉分类的排序和生存态势)
2. **图文工作台枢纽和清单**：`/pages/info/info-list` (用于统管上下架及删除操作和数据总览)
3. *弹出级* **创建修改文章编辑器页面/组件**：通过内嵌官方适配的 `custom-editor-tinymce` 组件提供强大的 HTML 可视化编辑能力。

## 四、接口与云函数设计

### C端云函数 (`/router/service/client/info/`)
- `getCategories`: 拉出允许在架暴露在外展示用的全部分类标引集。
- `getListByCategory`: 含上拉游标加载特性的拉取对应分类下标文章的列表(仅索取标题等轻型摘要字段，强制复合执行 `is_top DESC, publish_time DESC` 两级主副排列)。
- `getDetailAndRecord`: **核心机制**，在索取整篇正文全部字码流供给前面组件渲染使用的同时，于云端通过极简 `vk.baseDao.count` 开启一分钟极速防重墙查证，拦截期外即刻并发打点一条独立日志记录并原子级推进主文章表 `view_count` 递增。
- `getMyReadHistory`: 专属拉取归属于本人 `user_id` 的 `info-read-log` 表数据并且 `forginDB` 双向绑定带出原源文章标题和时点的连表流水线。

### B端云函数 (`/router/service/admin/info/`)
- `addCategory`/`updateCategory`: 管理类目标识。
- `addInfo`/`updateInfo`: 执行大型数据落库动作（处理好文本长字段落存的问题，内嵌了富文本自动脱水生成提要摘要拦截器）。
- `changeStatus`: 修改曝光展示允许状态指令执行。
- `getViewRecordList`: 读取谁看过某篇文件的证据表报名录。

## 五、数据与字段设计

### 1. `info-category` (头部分类基础库)
- `_id` 
- `name` (String): e.g. '文明之窗', '督导通知' 
- `sort` (Number): 排序大者居前或居后等控制力标定 
- `status` (Number): 是否允许开启上线 (0|1)

### 2. `info` (业务文献存放巨表)
- `_id` 
- `category_id` (String): 这个文章的头顶所属归口 
- `title` (String): 引领文字 
- `cover_img` (String): [可选] 外部列表展示用的封面大图链接（发布时若不填，则从后台自动截取富文本首图）
- `summary` (String): [可选] 列表展示用的短摘要，最多200字。（采用表单引导+服务端降级模式：后台供管理员手工填写引人入胜的提要；若留空，落库时系统自动从纯文本格式中截取前60字符填充兜底）
- `content` (String): 超长长度的不定长富含 HTML 标签的高级富文本字符串，或内含系统云存储托管的外链图文
- `view_count` (Number): 为免每次要联库查询性能损耗，设有的热数据反写访问量累加器 
- `is_top` (Boolean): 用于标识重磅内容，开启即列位于全局流队列的最高视界阵列。默认 false。 
- `status` (Number): 0(未发出), 1(在线) 
- `publish_time` (Timestamp): 设定这篇报告发出公诸于众的光阴节点

### 3. `info-read-log` (阅览证实附属日志库)
- `_id`
- `info_id` (String): 看哪一篇大作 
- `user_id` (String): 谁去点的 
- `read_time` (Timestamp): 点进正文屏那瞬间的确切定点

## 六、开发逻辑建议与边界
- **无图降级与封面自动抓取策略**：为保证列表的美观度和降低发布门槛，后台基于 Vue `watch` 并使用正则 `/img[^>]+src="([^">]+)"/i` 在编辑期间自动提取正文首图填入封面 `cover_img`。客户端渲染时，若数据流中仍未包含 `cover_img`，将启动包含 `.col-text` CSS 的沉浸式无图纯文本降级卡片，保证任何极端情况下的 UI 一致性。
- **自动提取摘要兜底机制**：彻底解决大段长文在列表中的生硬截断甚至留白。由云函数端强制接管：若用户在后台管理表单直接提交或未填写 `summary`，服务端在录入入库前采用正则暴起清洗所有 HTML 字符及多余挂载实体空格，提纯后精挑细选前 60 个正文字符作为展示提要。
- **关于 z-paging 全局基础设施建设**：因后续包含隐患排查、整改计划表等巨量长级滚动页面均需要极致分页体验。须对 `z-paging` 这套核心系统底层实施 `easycom` 全局引注，并在统一公用组件包中深度封装诸如无数据时的 `empty` 标准视图和加载动画等配置，彻底一劳永逸。
- 读取长篇幅文档内容属于重度高频且大内存占用行为。列表请求绝不拉取下挂`content`富文本详情，只做局部拉发以避免拥堵，并且列表检索支持搜索框 `keyword` 对 `title` 或 `summary` 的模糊下沉查询。
- 防止刷流水防伪造：对同一个信息同一用户在一分钟内的重复点入应当实施前后台共同摒弃忽略记次的手段优化存储压力并维系防作弊机制真实有效（甚至在`getDetailAndRecord`接口端设置短时间缓存防重）。


# Unified TabBar 设计提案

## 1. 架构目标
为文明生产管理系统微信小程序端建立全局最高级别的横向五栏式导航结构。此架构致力于“平衡信息获取的广度与现场执行的深度”，通过 5 项一级常驻入口彻底打通一线员工与管理中枢的交互脉络。

## 2. TabBar 视图结构设计

该系统底部导航将由以下 5 个业务单元构成：

### Tab 1: 【首页】 (Index / Dashboard)
- **路径定位:** `pages/index/index`
- **设计初衷:** 超级综合看板与快捷工作台。
- **核心模块:** 
  - 任务执行工作台（含快捷入口与核心数据摘要）。
  - 专业信息传达与备案信息的置顶高亮展示区块。
  - 参考 `docs/UI2/pages-index-index` 玻璃拟态设计样式。

### Tab 2: 【信息传达】 (Information Routing)
- **路径定位:** `pages/info/index` (之前创建的信息广场)
- **设计初衷:** 纯粹的信息流阅读汇聚地。
- **核心模块:** 
  - 顶部横向长廊多 Tabs 分类切换。
  - 直接进入列表查阅安全通知、政策解读、生产安排等，包含 60 秒防刷点击量等核心限制逻辑。

### Tab 3: 【任务执行】 (Task Execution)
- **路径定位:** 待定 / 新建专属页面聚合页，例如 `pages/workbench/task/index`
- **设计初衷:** 现场执行人员提报与回传中枢。
- **核心模块:** 
  - 现场信息（异常/问题）监督反馈。
  - 重点工作/重控点位专项反馈。

### Tab 4: 【计划执行】 (Plan Execution)
- **路径定位:** `pages/plan/list/index`
- **设计初衷:** 专注日常作业与既定派发动作追踪。
- **核心模块:** 
  - 日治理计划列表。

### Tab 5: 【我的】 (Mine / Profile)
- **路径定位:** `pages/user/mine/index`
- **设计初衷:** 个人数字化综合看台。
- **核心模块:** 
  - 个人基础身份验证状态与权限。
  - 阅读历史等个人足迹检索。
  - 账户设置等衍生功能。

## 3. 设计权衡与注意事项
- 我们使用了极具指向性的 **“5栏全开”架构**。这最大限度利用了小程序的生态空间，员工不需要进行二次寻找即可进入最重要的生产链路（信息了解、异常反馈、计划执行）。
- 需确保设计资源 (图标切图/原生字库) 可以完美承载 5 个菜单项不拥挤。
- 未来的业务衍生需控制在此五大模块内建立子集，不再增添新的主 Tab。
