## 三、Markdown 渲染方案（全局复用）

### 全局约定

- **渲染引擎**: `markdown-it`
- **目录导航插件**: `markdown-it-toc-done-right`（生成左侧悬浮目录导航）
- **安全配置**: `{ html: false, linkify: true, typographer: true }`（防XSS注入）

### 前台组件

**路径**: `xc/components/markdown-viewer/MarkdownViewer.vue`

**功能**:
- 接收 `content`（Markdown 字符串）prop，渲染为 HTML
- PC端（≥768px）：左侧悬浮目录导航（sticky 定位，top: 80px），右侧正文
- H5端（<768px）：目录折叠为顶部下拉按钮（"📖 目录"），点击展开下拉列表
- 目录项点击平滑滚动到对应标题位置
- 滚动时高亮当前可视区域对应的目录项
- 代码块语法高亮（highlight.js / prism.js）

**Props 定义**:
```js
{
  content: { type: String, required: true },      // Markdown 原文
  showToc: { type: Boolean, default: true },       // 是否显示目录
  maxTocDepth: { type: Number, default: 3 },       // 目录最大层级（h2=2, h3=3）
}
```

### 后台编辑器

**后台 Markdown 编辑器使用 cherry-markdown 组件**（用于培训文章课程、信息共享文章编辑等场景）。

## 四、附件管理方案（全局复用）

### 全局约定

- **存储**: 阿里云 OSS
- **文件大小限制**: 单文件 100MB
- **支持类型**: pdf/doc/docx/xls/xlsx/ppt/pptx/zip/rar/jpg/png/mp4
- **上传组件**: 基于 `vk-data-upload` 封装 `AttachmentUploader.vue`
- **附件展示组件**: `AttachmentList.vue`（显示文件名、大小、下载按钮）

### 数据库字段约定

所有含附件的业务数据使用内嵌数组字段 `attachments`：

```js
attachments: [
  {
    name: '操作手册.pdf',        // 文件名
    url: 'https://oss.xxx/...',  // OSS 下载地址
    size: 1048576,               // 文件大小（字节）
    type: 'pdf',                 // 文件扩展名
    upload_time: 1710288000000,  // 上传时间（时间戳）
  }
]
```

## 五、留言互动方案（全局复用）

### 全局约定

- **组件**: 自研互动留言组件 `CommentSection.vue`
- **路径**: `xc/components/comment-section/CommentSection.vue`
- **功能特性**:
  - 支持发表顶层留言、针对具体留言进行嵌套回复（展示为二级树形结构）。
  - 支持对留言或回复进行点赞。
  - 组件内部高度自治，仅需传入 `target_type` 和 `target_id`，组件内部独立完成分页拉取、发表和点赞的云函数调用，避免污染父页面数据流。
- **数据库字段约定**: 独立留言集合（如 `xc-info-comments`），字段必须包含：
  - `target_type` (String): 归属模块标识
  - `target_id` (String): 归属文章/实体的ID
  | `content` (String): 留言正文
  - `user_id` (String): 发表人
  - `parent_id` (String, 可选): 父级留言ID（代表这是一条回复）
  - `reply_to_user_id` (String, 可选): 被回复人的ID（用于二级以上的回复目标定位）
  - `likes_count` (Number): 点赞数
  - 通用字段 (创建时间、租户等)

## 七、可见性控制方案（全局复用）

### 全局约定

所有需要可见性控制的业务数据集合必须包含以下字段：

```js
{
  visibility: 'private',   // 可见性：public(所有部门) / private(仅本部门,默认) / targeted(指定部门)
  target_dept_ids: [],      // 目标部门ID数组（visibility=targeted 时必填）
  target_user_ids: [],      // 目标用户ID数组（可选精确控制）
}
```

### 中间件封装

**路径**: `service/middleware/modules/tenantFilter.js`

**功能**:
- 自动注入租户过滤条件到 `whereJson`

## 八、数据库通用字段约定

所有业务数据集合必须包含以下通用字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | String | 主键（系统自动生成） |
| `tenant_id` | String | 租户ID（必填，关联 xc-tenants._id） |
| `created_by` | String | 创建人用户ID |
| `created_at` | Number | 创建时间（时间戳，`Date.now()`） |
| `updated_by` | String | 更新人用户ID |
| `updated_at` | Number | 更新时间（时间戳） |
| `status` | Number | 状态（0=禁用/草稿 1=启用/发布 2=下架/归档） |
| `is_deleted` | Boolean | 软删除标记（false=正常 true=已删除） |
