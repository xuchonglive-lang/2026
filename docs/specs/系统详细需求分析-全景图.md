# 2026 办公应用平台 - 详细系统需求分析与 UI 全景图

**项目架构基座**: uni-app + uniCloud + vk-fun
**UI/UX 核心理念**: Minimal SaaS 极简工业风（主色 Slate 900，辅色 #165DFF，8px 栅格）
**数据隔离宪法**: 全局 `tenantFilter` 中间件

---

## 一、 系统全局 UI 设计与交互规范

### 1.1 自适应布局体系 (PC & H5 双模一致性)
- **核心布局容器 (`AppLayout`)**: 判断屏幕宽度，PC端渲染全宽容器，H5端渲染定宽容器。
- **导航体系**:
  - **PC 端**: 顶部完整导航条 (`TopNavBar`) + 左侧二级分类菜单 (`SideMenu`) + 底部版权页脚 (`PageFooter`)。
  - **H5 端**: 顶部简化标题栏 (`TopNavBar`) + 侧边抽屉菜单 (`DrawerMenu`) + 底部高频功能 TabBar (`BottomTabBar`)。
- **消息感知**: 导航栏右上角统一存在“铃铛”图标 (`BadgeIcon`)，内聚全局未读消息数量。超过 99 条显示 `99+`，点击进入统一消息中心。

### 1.2 全局复用组件库
- **文档渲染 (`MarkdownViewer`)**: 
  - 渲染器：`markdown-it` (防 XSS 配置 `html: false, linkify: true`)。
  - UI 表现：PC 端生成左侧固定悬浮目录（随滚动条动态高亮），H5 端将目录折叠至顶部下拉菜单（📖目录）。
- **互动留言 (`CommentSection`)**: 支持多级树形嵌套回复，每条留言包含头像、部门、内容、点赞按钮。组件内聚所有查询与发表的云端交互。
- **通用附件 (`AttachmentList`)**: 统一展示文件图标、大小、名称，并提供“点击预览（PDF等）或下载”操作。
- **数据范围配置 (`VisibilitySetter`)**: 后台表单通用块，单选框组（公开/仅本部门/指定部门），选择“指定部门”时平滑展开 `el-tree` 多选框。

## 二、 核心基座模块（底层引擎）

### 2.1 租户与组织架构 (Tenant Management)
**UI 设计**:
- **后台管理 (`list.vue`)**: 左右经典分栏。左侧为 `el-tree` 展示固定的两级部门结构（集团 -> 部室/车间），支持关键字过滤。右侧分为 `基本信息` 与 `成员管理` 两个 Tab 页（基于 `vk-data-form` 和 `vk-data-table`）。
- **视角切换器 (`DeptSelector`)**: 后台顶部专属组件（仅集团超级管理员可见）。使用分组 `el-select`。

**全流程与流转**:
1. **视角降维流程**: 集团超管在 `DeptSelector` 选择“质检部” -> 触发云函数 `switchView` 将目标 ID 持久化写入 `uni-id-users` 表 -> 页面组件重载 -> 后续所有云函数的 `tenantFilter` 自动读取该视图 ID 进行数据过滤，超管界面变为与“质检部管理员”完全一致。
2. **可见性校验流**: 业务列表请求 -> 中间件拦截 -> 拼装 `$or` 检索条件（`tenant_id === 我的部门` OR `visibility === 'public'` OR `(visibility === 'targeted' AND target_dept_ids 包含我的部门)`）。

### 2.2 用户与身份认证 (User Management)
**UI 设计**:
- **前端登录 (`login/index.vue`)**: H5 环境下无感静默跳转微信 OAuth。PC 浏览器内居中显示巨大的带参公众号二维码，右下角提供仅开发环境可见的“开发者账密登录”暗门。
- **拦截认证弹窗 (`DeptBindModal`)**: 全屏遮罩层，不可点击空白关闭。包含真实姓名输入框与拉取 `xc-tenants` 数据的级联选择器。

**全流程与流转**:
1. **公众号扫码强绑定流程**: PC 访问 -> 调微信接口获 120s 临时二维码 -> 用户用微信扫码 -> 未关注者弹出公众号关注页 -> 点击关注触发 `subscribe` 事件 -> 微信服务器推送到本系统云端 -> 云函数拉取头像/昵称，生成无 `tenant_id` 的“裸账号” -> PC 端轮询接口捕捉到事件完成，跳转业务页。
2. **账号激活审批流**: “裸账号”进业务页被 `DeptBindModal` 拦截 -> 用户提交真实姓名和部门申请 -> 数据落入 `xc-dept-applications` -> 对应的租户管理员登录后台进入“入驻审批” -> 点击“核准” -> 分配对应的内部小组（如“调度一班”） -> 系统分发用户权限及数据作用域。

### 2.3 权限与角色 (Permission Management)
**UI 设计**:
- **后台权限配置**: 编辑角色时包含两个核心 Tab。“菜单权限”使用 `el-tree` 勾选左侧导航可见域；“操作权限”使用以业务模块分组的 `Checkbox Group` 展示具体能力（如“删除课程”）。

**全流程与流转**:
1. **操作拦截流**: 页面渲染遇到含有 `v-if="$hasPermission('training:course:delete')"` 的按钮，比对 `$user.permission` 数组，无权限则 DOM 销毁。若恶意用户伪造请求直接调用 `admin/training/sys/delete` -> 触碰 `sys/` 目录内置中间件 -> 比对失败，强力阻断返回 `403`。

### 2.4 消息管理体系 (Message System)
**UI 设计**:
- **消息中心 (`list.vue`)**: 顶部横向滚动 Tab 切换通知类别。列表按时间倒序。未读消息标题使用 `font-weight: 600`，左侧增加 `8px` 蓝点指示器。
- **模板配置页 (`template.vue`)**: 提供文本域供管理员输入，右侧高亮提示可用占位符（如 `{{course_name}}`）。

**全流程与流转**:
1. **业务触发触达流**: 某部门管理员发布一门培训课程 -> 业务云函数完成数据落库 -> 异步调用推送服务 `wx-push/sys/batchSend` -> 系统加载对应的微信模板 ID 和当前配置 -> 将 `target_user_ids` 分拆为大小为 20 的批次 -> 使用 `vk.pubfn.batchRun` 向微信服务器并发推流 -> 推送成功或失败（如取消关注）的原因独立写入 `xc-messages` 日志库供溯源 -> 目标用户手机微信亮屏收到通知，点击卡片直接免密单点登录跳转进入具体的 `video-detail.vue`。

## 三、 功能业务模块（场景层）

### 3.1 培训业务 (Training Business)
**UI 设计**:
- **前台首页**: PC 端使用 `grid-template-columns: repeat(3, 1fr)` 呈现大卡片。缩略图（16:9）居上，下方显示时长及学习进度条。
- **视频详情 (`video-detail.vue`)**: 左右视区。左侧为带播放状态的章节列表，右侧居上为 `Video.js` 播放器。下方划分为四个 Tab（简介/目录/附件/留言）。
- **后台编辑**: 采用横向步骤条（Step 1: 基本信息 -> Step 2: 拖拽式章节管理 -> Step 3: 附件 -> Step 4: 可见性）。

**全流程与流转**:
1. **沉浸式学习流**: 用户打开章节 1 -> 每 5 秒前端自动调用 `saveProgress` 同步播放头秒数到 `xc-course-views` -> 用户突然关闭页面 -> 次日重新点击同一卡片 -> 弹出“上次观看到 12:45，是否继续？” -> 点击确认，控制播放器 `currentTime = 765` 并自动 `play()`。文章课程则监听 `onScroll` 到底部直接写 100% 进度。

### 3.2 信息共享 (Information Sharing)
**UI 设计**:
- **前台浏览**: 经典左右分栏（PC端），左侧树形点击一级分类，右侧显示瀑布流或列表。顶部提供子分类胶囊 Tab。
- **后台撰写**: 使用 `cherry-markdown` 组件，支持图片直接粘贴拖拽，自动上传 OSS 返回短链。

**全流程与流转**:
1. **知识流转流**: 员工进入政策文章详情 -> 前端组件触发生命周期 -> 云端写入 `xc-info-views` 阅读审计日志 -> 读者在底部 `CommentSection` 发布长篇探讨 -> 组件内局部刷新。

### 3.3 重点工作推进 (Key Tasks)
**UI 设计**:
- **工作全景图 (`AccordionList`)**: 嵌套三层手风琴列表。层级一：工作类型；层级二：工作集合；层级三：具体项目条目。条目右侧悬浮执行人圆形头像组与高亮状态（进行中/待验收）。
- **详情页 (`task-detail.vue`)**: “三段式”空间切割。
  - 第一段：骨干信息（大标题、发布人）。
  - 第二段：执行依托（使用蓝色边框独立卡片突出展示“工作标准”和附件）。
  - 第三段：时间轴式反馈区。区分蓝色“过程反馈”记录块与橙色“验收申请”记录块。

**全流程与流转**:
1. **闭环验收流**: 承接人点击底部“提交反馈” -> 弹窗选择“验收申请”类别，利用 `tiptap` 填报成果 -> 保存 -> 任务状态变更为 `待验收 (2)` -> 发布人收到微信通知 -> 发布人进入任务，滚动到最下方点击专属的“验收评价” -> 填写审核意见并选择“驳回” -> 任务退回 `进行中 (1)` -> 承接人收到驳回通知，继续修改并在原时间轴上追加新的过程反馈，直至最终通过验收。

### 3.4 专业管理 (Professional Management)
**UI 设计**:
- **模块导航**: 顶部 4 大胶囊 Tab：制度规范、管理网络、例行工作、我的文档。
- **管理网络图 (`OrgChart.vue`)**: 以卡片和连接线的拓扑图呈现，高亮本人，横向/纵向延展下属对口专员。
- **日历看板 (`FullCalendar`)**: 满屏月/周历，内部色块填充：蓝色（自身创建）、橙色（直系领导指派）、红色（上级对口专业指派）。点击色块弹窗展示。
- **我的文档**: 类网盘的左侧文件夹树+右侧文件列表体系，支持右键或下拉菜单执行“共享给同事”。

**全流程与流转**:
1. **专业指令下达流**: 总部“安全管理”专员在后台使用“角色映射”表关联了各厂区的安全员 -> 该专员进入前台日历 -> 框选 15 号到 17 号，选择“添加任务” -> 对象选定某厂区安全员 -> 该厂区安全员日历中立即出现红色色块 -> 17 号当天该安全员点击色块，上传现场检查照片，提交反馈 -> 总部专员在自己的视图中看到状态转为“已反馈”。

### 3.5 个人中心 (User Center)
**UI 设计**:
- **数据仪表盘 (`index.vue`)**: 顶部放置包含用户姓名、企业徽标的通行证卡片 `UserCard`。核心区域铺设 `GridMenu` (PC 3列，H5 2列)，以统一的 Icon 和角标聚合展现各项待办。
- **配置与报表**: 个人设置页使用 `Switch` 开关罗列各渠道通知。超级管理员后台的统计页铺满 `ECharts` 的漏斗图、折线图及雷达图。

**全流程与流转**:
1. **微服务式聚合流**: 用户打开首页 -> 前端发出 1 个并发指令 -> 云函数 `getSummary` 内部使用 `Promise.all` 向五个不同的数据库表 (`xc-messages`, `xc-key-tasks`, `xc-course-views` 等) 并发查询当前 `user_id` 匹配的未读和未完成数量 -> O(1) 组装返回前端渲染角标。

### 3.6 AI 信息分析 (AI Analysis) - 纯后台模块
**UI 设计**:
- **策略工坊 (`execute.vue`)**: 面包屑或横向步骤条指引执行路线。
- **提示词 IDE**: 内嵌代码编辑器组件，支持占位符高亮。右侧提供可用的环境变量面板，点击即插入光标处。

**全流程与流转**:
1. **智慧洞察流**: 管理员上传一份《2026行业标准.pdf》 -> Node.js 提取文本 -> 根据所选模板引擎将 `{{文档内容}}` 替换为实体字符串 -> 携带系统配置的加密 AES 解码出来的 `API Key` 向第三方大模型发起 Stream 请求 -> 前端打字机效果输出 Markdown 报告 -> 点击“保存为 PDF” -> 云端开启 Puppeteer 或专用转换库生成二进制流 -> 传阿里云 OSS 固化，生成永久溯源档案。
